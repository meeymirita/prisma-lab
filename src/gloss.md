ORM :: библиотека, которая превращает вызовы в коде в запросы к базе и обратно; Prisma — ORM для TypeScript
schema.prisma :: файл-описание моделей, связей и настроек Prisma: «чертёж» для клиента и миграций
Prisma Client :: типизированный клиент, который генерируется по схеме и через который код ходит в базу
prisma.config.ts :: конфигурация Prisma CLI в Prisma 7: адрес базы, пути, сид
driver adapter (адаптер) :: слой между клиентом Prisma и драйвером базы; у нас `@prisma/adapter-pg` поверх `pg`
generate :: команда, создающая клиент по схеме; в Prisma 7 не запускается автоматически
Prisma 7 / Prisma 8 :: две разные модели работы; 8 — release candidate (контракт вместо схемы, `db.orm`); лаба — на 7
db pull (интроспекция) :: чтение существующей базы и запись её описания в схему
baseline :: нулевая миграция, которой «принимается» существующая база; не выполняется, а отмечается применённой
миграция :: версионированное изменение базы (SQL-файл) с контрольной суммой; журнал — таблица `_prisma_migrations`
shadow database :: временная база, на которой Prisma проигрывает историю миграций при `migrate dev`
migrate dev / migrate deploy :: создать и применить миграцию на разработке / только применить на CI и проде
drift :: расхождение реальной базы и истории миграций (кто-то менял базу мимо миграций)
expand / contract :: безопасная смена структуры: добавить новое, перенести данные, переключить код, убрать старое
backfill :: заполнение новой колонки из старой данными, порциями, идемпотентно
NOT VALID / VALIDATE :: ограничение «для новых строк сразу, для старых — проверить позже без долгой блокировки»
@map / @@map :: соответствие имени поля или модели в коде и в базе
enum :: тип с ограниченным набором значений; в PostgreSQL — отдельный тип
relationMode :: режим связей: `foreignKeys` (настоящие ключи в базе) или `prisma` (эмуляция на стороне клиента)
include / select / omit :: что вернуть из запроса: со связями, только перечисленное, всё кроме перечисленного
N+1 :: один запрос за списком и ещё N запросов за связанными данными в цикле
relationLoadStrategy :: способ загрузки связей: `query` (несколько запросов) или `join` (один с соединением)
cursor / keyset-пагинация :: постраничный обход «после такого-то id» вместо `OFFSET`
EXPLAIN :: показ плана выполнения запроса; `ANALYZE` выполняет его и даёт реальное время
Seq Scan / Index Scan :: полный перебор таблицы / поиск по индексу
составной индекс :: индекс по нескольким колонкам; порядок колонок важен
GIN / триграммы (pg_trgm) :: индекс и расширение для быстрого поиска «содержит» (LIKE '%…%', ILIKE)
частичный индекс :: индекс только по части строк (`WHERE …`)
$queryRaw / $executeRaw :: сырой SQL с параметрами (значения передаются отдельно от текста)
SQL-инъекция :: вклейка пользовательских данных в текст запроса, из-за чего данные становятся командой
TypedSQL :: возможность Prisma превращать `.sql`-файлы в функции с типизированным результатом (preview)
Decimal :: точное десятичное число (`Prisma.Decimal`, decimal.js); для денег; в базе — `numeric(12,2)`
BigInt :: целое больше 2⁵³; в JSON не сериализуется без явного преобразования
timestamptz :: тип PostgreSQL «момент времени» (хранится в UTC); `timestamp` — «часы на стене» без пояса
transaction (транзакция) :: «всё или ничего»: набор операций, который либо применяется целиком, либо откатывается
интерактивная транзакция :: `$transaction(async tx => …)`: внутри можно читать и принимать решения
isolationLevel :: уровень изоляции транзакций: `ReadCommitted`, `RepeatableRead`, `Serializable`
гонка (race condition) :: результат зависит от порядка параллельных операций
потерянное обновление :: два «прочитал — изменил — записал» затирают друг друга
write skew :: две транзакции читают одно, пишут разное и вместе нарушают правило
оптимистичная блокировка :: запись «если версия не изменилась», иначе повтор
пессимистичная блокировка (FOR UPDATE) :: захват строк до конца транзакции
SKIP LOCKED :: пропуск уже заблокированных строк; основа очереди в таблице
дедлок :: взаимная блокировка двух транзакций; база отменяет одну
P2034 :: код Prisma «конфликт записи или дедлок» — транзакцию нужно повторить
EXCLUDE (exclusion constraint) :: ограничение «нет двух строк, у которых это равно, а это пересекается»
tstzrange :: диапазон моментов времени; `&&` — «пересекаются»
btree_gist :: расширение, позволяющее смешивать `=` и `&&` в одном GiST-индексе
идемпотентность :: повтор операции даёт тот же результат, что и одно выполнение
идемпотентный ключ :: внешний уникальный номер операции (`ext_ref`), по которому повтор распознаётся
ledger (журнал проводок) :: учёт денег в виде неизменяемых записей двойной записи; остаток — сумма
двойная запись :: каждая операция — пара проводок (дебет и кредит), сумма которых равна нулю
сверка (reconciliation) :: проверка согласованности данных; расхождение нужно найти и объяснить
триггер :: функция базы, срабатывающая на изменение строки (у нас — аудит и проверка баланса)
$extends (расширение клиента) :: надстройка над клиентом: `query`, `result`, `model`, `client`
soft delete :: «удаление» отметкой `deletedAt` вместо настоящего `DELETE`
мультитенантность :: несколько изолированных «хозяев» данных (у нас — филиалов) в одной системе
RLS (Row Level Security) :: политики базы, показывающие строки только «своего» тенанта
set_config / параметр сессии :: передача филиала в базу; `true` — только до конца транзакции
роль базы :: учётная запись с набором прав; у приложения — без DDL и без права стирать журналы
GRANT / REVOKE :: выдача и отзыв прав; можно на колонки
пул соединений :: набор открытых соединений с базой, которыми пользуются запросы по очереди
max_connections :: предел соединений сервера PostgreSQL
singleton клиента :: один экземпляр `PrismaClient` на процесс
PgBouncer :: пулер соединений перед PostgreSQL; для Prisma — режим `transaction`
pg_stat_statements :: расширение PostgreSQL: статистика по запросам (число вызовов, время)
statement_timeout / lock_timeout :: серверные «будильники» на длительность запроса и ожидание блокировки
шаблонная база (TEMPLATE) :: база-эталон, которую копируют для каждого теста
Vitest :: инструмент запуска тестов для TypeScript
CI :: автоматическая проверка при каждом изменении (миграции с нуля, типы, тесты)
OpenTelemetry :: стандарт трассировки; Prisma умеет создавать span'ы запросов
ADR :: запись архитектурного решения: что выбрали, из чего выбирали, почему
